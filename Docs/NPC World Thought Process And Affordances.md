# NPC World Thought Process And Affordances

## 1. Purpose

Define the intended NPC world-thinking model before deeper work on idle behaviour, roles, jobs, schedules, combat awareness, or movement AI.

This is primarily a design and alignment pass. It is not a full AI implementation pass.

## 2. Current Implementation Summary

Current live exploration/world behaviour is still a transitional model.

- `Assets/ExplorationTurnManager.cs` gives each exploration NPC one deterministic turn and resets move points before `Character.ExecuteTurnActions()`.
- `Assets/Objects/Character.cs` `ExecuteTurnActions()` now resets a per-turn decision result, runs the state machine once, and only falls back to `MoveToCellsOfInterest()` if the state machine left the turn unresolved.
- `Assets/StateMachine.cs` `IdleState.UpdateState(...)` now makes one bounded decision per world turn instead of running an AP-driven idle loop.
- `Assets/StateMachine.cs` `TrueIdleState.UpdateState(...)` explicitly consumes the turn without movement.
- `Assets/Objects/Character.cs` `CellsOfInterest` is currently a raw `List<Vector2Int>` of cell coordinates, populated by `EvaluateCellsOfInterest(...)` using a narrow shelter heuristic:
  - passable cell
  - indoors
  - rainy weather

That means current NPC world behaviour is still mostly:

- state-based
- cell-centric
- reactive
- weakly role-aware

It is not yet a real world-intent / affordance-driven system.

## 3. Current Gaps

Important current gaps:

- role/job/profession data exists, but it does not currently drive live exploration decisions
- `FrequentNeeds` is used for generated item desires, not movement or workplace choice
- `CraftingType` / `IsCraftsman` exists, but is not used by `IdleState` or `ExecuteTurnActions()`
- objects do not currently advertise generic NPC-facing affordances
- `CellsOfInterest` means “candidate shelter cells”, not “interesting world opportunities”
- random movement still exists as a bounded fallback
- combat/world awareness is still limited and not yet unified with area-scale world thinking

## 4. NPC World Turn Contract

A normal NPC exploration/world turn should follow this contract:

1. Can I act?
2. What matters most right now?
3. Choose one intention.
4. Attempt one bounded action.
5. Record the result.
6. End the turn cleanly.

This is the governing rule:

> One NPC world turn = one bounded decision.

The world turn should not be an AP-spending exploration loop.

## 5. One Bounded Decision Rule

A normal world turn should not keep looping until AP is empty.

Instead, the NPC should:

- inspect enough context to choose an intention
- perform one bounded attempt
- stop

Bounded outcomes include:

- moved
- idled
- worked in place
- interacted
- continued travelling
- failed movement
- no action available
- skipped because invalid/incapacitated

All of those are valid turn outcomes.

## 6. Idle Is Valid

Idle is not an error.

An NPC should be allowed to:

- stand still
- stay at their post
- keep watching
- rest in place
- do a minimal in-place role action
- intentionally do nothing

If idling is an appropriate outcome, the turn should resolve cheaply and quietly.

## 7. Failed Movement Is Valid

Failed movement is not automatically a logic failure.

Examples:

- no move points
- blocked tile
- no valid adjacent step
- target became invalid
- destination no longer meaningful

A failed movement attempt should still count as a resolved world turn unless the NPC is explicitly continuing a valid task in a future turn.

## 8. No Point Of Interest Is Valid

No point of interest is not inherently a warning-level problem.

If an NPC has:

- no urgent need
- no valid role target
- no valid social opportunity
- no current task continuation
- no good local affordance

then a no-op or local idle outcome is correct.

The system should not assume that “no point of interest” means “wander randomly.”

## 9. Current NPC World Turn Behaviour

### `IdleState`

Current meaning:

- generic exploration/world fallback state for non-hostile actors
- now makes one bounded choice:
  - random movement attempt
  - idle action
  - default idle

Important limitation:

- it does not actually inspect role, workplace, nearby useful objects, needs, social opportunities, or area type in a meaningful way

### `TrueIdleState`

Current meaning:

- explicit “do not act this turn” state
- consumes AP and MP
- prevents movement

This is currently closer to a “stay put / dormant / off-duty / non-participating” state than a living social idle.

### `CellsOfInterest`

Current meaning:

- raw candidate cell coordinates
- currently generated by weather/indoors shelter logic in `Character.EvaluateCellsOfInterest(...)`
- not role-aware
- not object-aware
- not affordance-aware
- not task-aware

### Fallback

Current exploration fallback remains:

- if the state machine did not resolve the turn, `Character.MoveToCellsOfInterest()` may run
- if there are no valid cells, it can attempt one bounded random movement fallback

This is now bounded, but it is still a legacy heuristic and should not become the long-term world-thinking model.

## 10. NPC World Thought Process

Recommended thought order for a normal world turn:

1. Can I act?
   - alive?
   - present in loaded area?
   - not destroyed?
   - valid location?
   - not incapacitated?

2. Am I already committed to something?
   - travelling to a destination
   - working
   - guarding
   - resting
   - following
   - using a station

3. Do I perceive something important?
   - immediate danger
   - blocked route
   - notable event
   - nearby relevant person/object
   - future: line of sight, sound, witnesses, calls for help

4. Do I have role/job behaviour available?
   - blacksmith seeks smithing affordance
   - guard seeks guard or patrol affordance
   - innkeeper seeks customer or bar affordance
   - patron seeks drink/sit/social affordance

5. Do I have personal needs?
   - hunger
   - fatigue
   - pain
   - comfort
   - morale
   - boredom

6. Do I have social opportunities?
   - friend nearby
   - faction member nearby
   - customer nearby
   - family nearby

7. Is there an area-appropriate local affordance nearby?

8. If not, choose a scene-aware idle fallback.

9. Resolve one bounded action.

10. End turn.

## 11. Affordance Definition

An affordance is:

> What a thing, place, person, or event offers to an NPC.

Examples:

- `Smithing`
- `Metalwork`
- `Workstation`
- `Rest`
- `Sleep`
- `Sit`
- `Drink`
- `Socialise`
- `Trade`
- `GuardPost`
- `PatrolRoute`
- `Pray`
- `Food`
- `Shelter`
- `CrimeReport`
- `Inspect`
- `Loot`

An affordance is not the NPC’s desire. It is the opportunity being offered by the world.

## 12. InterestTag Definition

An `InterestTag` is:

> A tag used by NPC logic to search for relevant world opportunities.

Examples:

- blacksmith interest tags:
  - `Smithing`
  - `Metalwork`
  - `Workstation`
  - `Trade`
  - `Rest`

- guard interest tags:
  - `GuardPost`
  - `PatrolRoute`
  - `SuspiciousActivity`
  - `CrimeReport`
  - `OtherGuards`

## 13. InterestCandidate Definition

An `InterestCandidate` is:

> A concrete possible target for a world-turn decision.

A candidate may represent:

- an object
- a cell
- a location marker
- a character
- an event
- a sound source
- a task destination
- a remembered destination later

This is intentionally broader than `CellsOfInterest`.

## 14. RoleInterestProfile Definition

A `RoleInterestProfile` is:

> A role/job/profession-level weighted set of desired affordances.

Examples:

- blacksmith:
  - `Smithing` 100
  - `Metalwork` 80
  - `Workstation` 60
  - `Trade` 30
  - `Rest` 10

- guard:
  - `GuardPost` 100
  - `PatrolRoute` 80
  - `SuspiciousActivity` 70
  - `CrimeReport` 60
  - `OtherGuards` 25

- tavern patron:
  - `Drink` 80
  - `Sit` 60
  - `Socialise` 70
  - `Warmth` 20

## 15. PersonalInterestProfile Definition

A `PersonalInterestProfile` is:

> Character-specific modifiers to role interests based on personality, traits, needs, relationships, mood, history, or temporary state.

Examples:

- hungry NPC boosts `Food`
- tired NPC boosts `Rest`
- cowardly NPC boosts `Safety`
- social NPC boosts `Socialise`
- loyal guard boosts `GuardPost`
- curious character boosts `Inspect`

This should modify the role layer, not replace it.

## 16. Objects, Places, People, And Events As Interest Providers

The long-term model should let world entities advertise opportunities.

### Objects

- anvil: `Smithing`, `Metalwork`, `Workstation`
- forge: `Smithing`, `HeatSource`, `Workstation`
- bed: `Sleep`, `Rest`
- chair: `Sit`, `Rest`, `Socialise`
- tavern bar: `Drink`, `Socialise`, `Trade`, `WorkInnkeeper`
- shrine: `Pray`, `Reflect`
- chest: `Store`, `Loot`

### Places / Cells / Area Markers

- gate: `GuardPost`, `Entrance`
- market square: `Trade`, `Browse`, `Socialise`
- campfire: `Warmth`, `Rest`, `Socialise`
- patrol point: `PatrolRoute`

### People

- customer: `Trade`
- friend: `Socialise`
- ally under attack: `Assist`, `Witness`, `ReportCrime`

### Events

- theft witnessed: `CrimeReport`
- fresh corpse: `Inspect`, `Mourn`, `Loot`, `ReportCrime`
- loud noise: future `Investigate`

## 17. Examples By Role

### Blacksmith

- primary interests: `Smithing`, `Metalwork`, `Workstation`
- secondary interests: `Trade`, `Rest`
- should not hardcode “go to anvil”
- should seek any object/location advertising smithing-style affordances

### Guard

- primary interests: `GuardPost`, `PatrolRoute`, `SuspiciousActivity`
- likely low wander bias
- should often remain at post if no threat exists

### Innkeeper

- primary interests: `Bar`, `Customer`, `Drink`, `Trade`, `Clean`
- should prefer staying near service affordances

### Tavern Patron

- primary interests: `Drink`, `Sit`, `Socialise`, `Warmth`
- wander should be occasional, not default

### Traveller

- primary interests: `Rest`, `Shelter`, `Trade`, `Route`, `Food`

### Dog / Animal

- primary interests: `Owner`, `Food`, `Wander`, `SleepSpot`, `Noise`
- should use species/personal profile, not human workstation logic

- `Titles`
- `LoadoutNames`
- `FrequentNeeds`
- `NewsType`
- `IsCraftsman`
- `CraftingType`
- `StatModifiers`

Current live uses:

- generation/loadouts
- stat modifiers
- titles
- dialogue/news flavour
- need generation in `Assets/NPCManager.cs`

Current non-use:

- exploration movement
- workplace choice
- object choice
- idle preference
- scene-aware fallback

Conclusion:

- role data can support interest tags later
- the safest extension point is `NPCRoleData`
- adding future `InterestTags` / weighted interests to JSON is structurally compatible with the current design

## 19. Current Object / Place Affordance Audit

Current object/place reality:

- `BaseObject` and object subclasses exist
- cells already carry useful metadata:
  - `Terrain`
  - `EnvironmentalTagFlags`
  - `ResourceTagFlags`
  - `isIndoors`
  - ownership
  - occupants / objects
- objects currently provide player interactions, not generic NPC-facing affordance tags
- items/constructables already expose useful identity fields:
  - `ItemTypes`
  - `ObjectString`
- there is no general occupancy/reservation system for world-use stations beyond item `Reserved`

Examples already present in content/code:

- `Anvil` exists as both constructable content and placed object class
- `Bed` exists as constructable content
- cells already distinguish indoor shelter

Conclusion:

- the most natural future affordance locations are:
  - object classes / object data
  - cell or area markers for place-level affordances
  - event wrappers for situational affordances

## 20. Current `CellsOfInterest` Behaviour

Current live meaning:

- `CellsOfInterest` is a list of `Vector2Int` cell coordinates
- assigned only by `Character.EvaluateCellsOfInterest(...)`
- currently selected by `IsValidCellOfInterest(...)`
- present criteria are mostly:
  - passable
  - indoors when raining

This is not a true interest system.

It is best understood as:

> A narrow legacy shelter-cell heuristic used by exploration fallback movement.

## 21. Scene-Aware Idle Fallback

Pure fallback idle should be scene-aware.

The final fallback should ask:

- how many nearby actors wandered recently?
- how many are standing still?
- how many are resting, working, or socialising?
- what kind of area is this?
- did I move recently?
- does my role expect me to hold position?
- does my personality favour wandering?

Possible fallback behaviours:

- `StandStill`
- `LookAround`
- `Wander`
- `SitOrRest`
- `WorkInPlace`
- `SocialGlance`
- `InspectNearby`
- `GuardPostIdle`
- `SleepOrRest`
- `DoNothing`

Important rule:

> Random wandering is one possible idle behaviour, not the default failure fallback.

If many nearby NPCs already wandered recently, bias toward staying put.

If the area is lively and too static, allow some wanderers.

This should be weighted and contextual, not hardcoded.

## 22. How This Avoids Every NPC Wandering

This model prevents the “all NPCs wander because nothing else was found” problem by:

- treating no-op as valid
- preferring role/task continuity first
- treating idle as intentional
- letting scene context suppress excessive wandering
- moving random wander out of the emergency fallback role

## 23. How This Avoids Hardcoded Role-Object AI

This model avoids hardcoded logic like “blacksmith goes to anvil” by separating:

- NPC interests
- world affordances
- candidate matching

That means:

- role data can be extended in JSON
- modded objects can participate by advertising affordances
- new workplaces do not require new hardcoded NPC behaviour branches

## 25. Suggested Staged Implementation Plan

### Stage 1

- preserve one bounded NPC decision per turn
- normalise idle/no-op as valid
- document thought process and affordance terms

### Stage 2

- add a small set of affordance tags to a few existing world objects/locations
- add weighted interest tags to a few roles
- build simple candidate discovery and matching

### Stage 3

- add task continuity
- let NPCs continue travelling toward a chosen interest over several turns

### Stage 4

- add reservation / occupancy
- prevent overcrowding one station

### Stage 5

- add scene-aware idle distribution
- reduce herd wandering

### Stage 6

- add personality / needs / relationship / schedule modifiers

### Stage 7

- integrate perception and combat awareness:
  - sight
  - hearing
  - calls for help
  - witnesses
  - reaction behaviour

### Stage 8

- integrate future speed/readiness scheduling

## 28. Remaining Risks

- other NPC states still use older AP-loop logic and are not yet aligned to the bounded world-turn contract
- combat and exploration are still split by active manager, so uninvolved bystanders remain frozen during combat
- object affordances do not yet exist as first-class data
- role data still influences flavour/stats/needs more than live world behaviour
- `CellsOfInterest` may remain misleading if treated as a true intent system

## 29. Recommended Next Phase

Build the smallest real affordance-driven prototype:

1. Keep the bounded world-turn contract.
2. Add affordance tags to a tiny set of objects/places:
   - anvil
   - bed
   - chair
   - bar / hearth if present
3. Extend a tiny set of role profiles with weighted interests:
   - blacksmith
   - guard
   - villager
4. Add a small `InterestCandidate` discovery layer.
5. Prefer nearest/highest-weighted valid candidate.
6. Only use random wandering as explicit idle behaviour, not emergency fallback.
